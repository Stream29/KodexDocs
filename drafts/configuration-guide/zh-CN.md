# 配置作用域与自动会话标题（首批草稿）

> 本页是说明书草稿，不是已确认的网站目录。当前 CLI 的界面标签仍以源码中的英文为准。

## 先记住这三件事

- **当前会话**是正在打开的会话快照；修改它只改这个目标。
- **新会话默认值**保存在全局设置中，创建新的会话草稿时复制一份；不会回写所有已经存在的会话。
- **自动会话标题**是另一组全局设置，和会话使用的模型、推理强度、服务层级不是同一个开关。

## 三种作用域

| 位置 | 控制什么 | 什么时候生效 |
| --- | --- | --- |
| `Settings > Current session` | 当前选中会话的模型、推理强度、服务层级、提问模式和工作目录 | 修改提交到这个会话的设置快照后立即影响后续操作 |
| `Settings > New session` 的 `Model behavior` | 新建会话草稿的初始模型、推理强度、服务层级和提问模式 | 下一个新建的草稿创建时读取；已经打开的草稿保持自己的本地值 |
| `Settings > New session` 的 `Title generation` | 自动标题开关、Title model、Title reasoning | 下一次满足条件的首条文本提交尝试标题生成；不改写已有标题 |

全局设置的数据模型把 `new_session` 与 `session_title` 分开保存。`new_session` 是“复制给新线程的默认值”，而不是每个会话的实时绑定；会话创建后，配置存放在该会话自己的 `KodexAgentSettings` 中。

## 从状态栏进入

状态栏的配置按钮显示当前目标的模型、推理强度，以及非 `default` 时的服务层级。打开第一个按钮后按层级选择：

1. **Model**
2. **Reasoning**
3. **Service tier**

第二个按钮是 **Questions**，选择 `ask user` 或 `no question`。工作目录按钮打开目录选择器，右侧的 **Settings** 打开设置页。正在运行的会话和新会话草稿都使用这组入口；设置页会绑定到打开入口时的那个目标，而不是之后临时切换的目标。

状态栏适合快速改当前目标。要改“以后新建会话的默认值”，进入设置页的 **New session**，不要把状态栏改动误认为全局默认值改动。

## 从设置页进入

在 Settings 左侧选择：

- **Current session**：查看和修改已物化会话，或查看当前新会话草稿的会话级快照。
- **New session**：修改全局的新会话默认值；`Model behavior` 下的四项对应模型、推理、服务层级和 Questions。
- **Title generation**：独立的自动会话标题开关、Title model 和 Title reasoning。该组控件位于 New session 页面，但写入的是全局 `session_title` 设置，而不是当前草稿的模型配置。

修改 New session 默认值后，不要期待已经打开的草稿自动变成新值。创建草稿时，应用从当前全局默认值生成一次 `initialSettings`；之后草稿由自己的 ViewModel 管理，点击状态栏或 Current session 页面只修改这个草稿。

## 自动会话标题何时真的发生

自动标题不是“打开控件就会生成”。一次会话只有在以下条件都满足时才有机会生成：

- 有自动标题配置；
- 该会话的标题仍是默认的 `Session N` 形式；
- 第一次被接受的输入中包含非空文本；
- `Automatic session title` 已启用。

满足条件后，Kodex 才会为这一次机会启动一个独立的标题请求。请求使用 **Title model**；若没有显式设置模型，则使用编译时的 `gpt-5.3-codex-spark`。请求的推理强度来自 **Title reasoning**，不是会话的 `Reasoning` 字段。生成结果仍会检查当前标题没有被手动改名，然后才写回。

这是一次性、尽力而为的辅助请求。手动重命名会使正在等待的自动结果失效；关闭开关、手动命名或无文本输入都不能据此推断会把现有会话批量重命名。

## 如何验证

- **控件可见性**：使用真实 CLI 录制查看状态栏、Settings、New session 的 Model behavior 和 Title generation 控件。
- **行为生效**：检查设置文件的持久化值，或用有明确断言的单元测试/模拟标题生成器检查请求模型、推理强度、一次性触发和结果写回。
- **不要混淆两者**：禁网的设置页演示只能证明控件能显示和修改，不能证明真实模型请求已经生成自动标题。本首批录制没有把离线设置画面当作标题生成证据。
