# 設定作用域與自動工作階段標題（首批草稿）

> 本頁是說明書草稿，不是已確認的網站目錄。目前 CLI 的介面標籤仍以原始碼中的英文為準。

## 先記住三件事

- **目前工作階段**是正在開啟的工作階段快照；修改只作用於這個目標。
- **新工作階段預設值**保存在全域設定中，建立新工作階段草稿時複製一份；不會回寫所有已存在的工作階段。
- **自動工作階段標題**是另一組全域設定，與工作階段使用的模型、推理強度、服務層級不是同一個開關。

## 三種作用域

| 位置 | 控制內容 | 何時生效 |
| --- | --- | --- |
| `Settings > Current session` | 目前選取工作階段的模型、推理強度、服務層級、提問模式與工作目錄 | 修改寫入這個工作階段的設定快照後，立即影響後續操作 |
| `Settings > New session` 的 `Model behavior` | 新工作階段草稿的初始模型、推理強度、服務層級與提問模式 | 下一個新草稿建立時讀取；已開啟的草稿保留自己的值 |
| `Settings > New session` 的 `Title generation` | 自動標題開關、Title model、Title reasoning | 下一次符合條件的首段文字提交時嘗試產生標題；不改寫既有標題 |

全域設定的資料模型把 `new_session` 與 `session_title` 分開保存。`new_session` 是「複製給新執行緒的預設值」，不是每個工作階段的即時綁定；建立後，設定會放在工作階段自己的 `KodexAgentSettings` 中。

## 從狀態列進入

狀態列的設定按鈕顯示目前目標的模型、推理強度，以及非 `default` 時的服務層級。開啟第一個按鈕後依層級選擇：

1. **Model**
2. **Reasoning**
3. **Service tier**

第二個按鈕是 **Questions**，可選 `ask user` 或 `no question`。工作目錄按鈕會開啟目錄選擇器，右側的 **Settings** 會開啟設定頁。工作階段與新工作階段草稿都使用這些入口；設定頁會綁定開啟入口時的目標，而不是之後暫時切換的目標。

狀態列適合快速修改目前目標。若要修改「往後新建工作階段的預設值」，請到設定頁的 **New session**，不要把狀態列修改誤認為全域預設值修改。

## 從設定頁進入

在 Settings 左側選擇：

- **Current session**：查看並修改已物化的工作階段，或查看目前新工作階段草稿的工作階段級快照。
- **New session**：修改全域的新工作階段預設值；`Model behavior` 下的四項對應模型、推理、服務層級與 Questions。
- **Title generation**：獨立的自動標題開關、Title model 與 Title reasoning。這組控制項位於 New session 頁面，但寫入的是全域 `session_title` 設定，不是目前草稿的模型配置。

修改 New session 預設值後，不要期待已開啟的草稿自動變成新值。建立草稿時，應用程式從當時的全域預設值產生一次 `initialSettings`；之後草稿由自己的 ViewModel 管理，狀態列或 Current session 頁面只修改這個草稿。

## 自動工作階段標題何時真的發生

自動標題不是「看見控制項就會產生」。只有在以下條件都成立時，一個工作階段才有機會產生：

- 有自動標題配置；
- 工作階段標題仍是預設的 `Session N` 格式；
- 第一次接受的輸入包含非空文字；
- `Automatic session title` 已啟用。

條件成立後，Kodex 才會為這次機會啟動獨立的標題請求。請求使用 **Title model**；若沒有明確設定模型，則使用編譯時的 `gpt-5.3-codex-spark`。請求的推理強度來自 **Title reasoning**，不是工作階段的 `Reasoning` 欄位。產生結果仍會檢查目前標題沒有被手動修改，才會寫回。

這是一次性、盡力而為的輔助請求。手動重新命名會使等待中的自動結果失效；關閉開關、手動命名或沒有文字輸入，都不能據此推斷會批次重新命名現有工作階段。

## 如何驗證

- **控制項可見性**：使用真實 CLI 錄製查看狀態列、Settings、New session 的 Model behavior 與 Title generation 控制項。
- **行為生效**：檢查設定檔的持久化值，或用有明確斷言的單元測試／模擬標題產生器檢查請求模型、推理強度、一次性觸發與結果寫回。
- **不要混淆兩者**：離線的設定頁示範只能證明控制項能顯示和修改，不能證明真實模型請求已產生自動標題。本首批錄製沒有把離線設定畫面當作標題產生證據。
